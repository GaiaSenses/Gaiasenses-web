O clima de um
lugar real vira
a sua obra.

Você aponta o globo para um ponto do planeta. O site busca a temperatura, a chuva, os raios e as queimadas daquele lugar, naquele momento, e entrega esses números para as obras que estão no ar. Este guia é para colocar a sua lá dentro.

Demonstração ao vivo · exemploClima temp 24.0 °C · chuva 0.0 mm/h

Isto é uma animação declarada, rodando. Ela pediu dois dados — temperature e rain — e o site os entregou. Todo o resto é o seu p5. O código está mais abaixo, inteiro.

Antes de tudo

Três coisas, uma vez só

  1. Uma conta no GitHub

    É onde o projeto guarda tudo, e você vai usá-lo só pelo navegador. Em github.com/signup: e-mail, senha, um nome de usuário, e confirmar. Gratuito, uns três minutos.

  2. Um convite para o repositório

    Ter conta não basta — alguém da equipe precisa te dar acesso. Mande o seu usuário e aceite o convite que chega por e-mail. Sem isso, o botão de enviar arquivos nem aparece.

  3. A ferramenta da sua obra

    Para som, o Pure Data vanilla, de puredata.info. Para imagem, nada além de um editor de texto — o código que você já tem no OpenProcessing ou no editor do p5 serve de ponto de partida.

Você não instala mais nada. Nem Node, nem compilador, nem servidor. O robô do projeto faz essa parte, e você recebe um link.

Caminho A · som

Um patch de Pure Data

O seu patch escuta canais. Para receber um dado do mundo, basta um objeto de receive com o nome dele. Não há arquivo de configuração para preencher nem ninguém para avisar: quando você envia, o sistema lê os objetos que você usou e liga tudo sozinho.

é literalmente isto 
[r gaia.temp]   ← a temperatura de onde o globo está apontando

Como a pasta precisa estar

minha-peca/ 
minha-peca/
├── main.pd          o patch principal, com esse nome exato
├── patch.json       a ficha da obra
├── Libs/            todas as suas abstrações .pd vão aqui
│   ├── minhaAbs.pd
│   └── outraAbs.pd
├── Audios/          arquivos .wav ou .aif, se a peça usar
└── Extras/          imagens e outros arquivos

Três regras causam quase todos os erros:

  • O principal precisa se chamar main.pd e ficar na raiz.
  • Toda abstração vai dentro de Libs/. Nenhuma solta na raiz.
  • O main.pd precisa conter [declare -path Libs], em qualquer lugar. Sem ele o Pd não acha as suas abstrações.

A armadilha silenciosa: maiúsculas importam. Se o arquivo é MinhaAbs.pd e você escreve [minhaabs], funciona no seu Mac e quebra no servidor. O sistema avisa — mas é melhor já nascer certo.

Limitação conhecida. O compilador aceita apenas um graph no patch principal — aquelas caixas com “graph on parent” ligado. Se você usa várias, mova-as para abstrações em Libs/.

Um patch que funciona

A temperatura vira a altura de uma nota: quanto mais quente o lugar, mais aguda.

patches/exemplo-clima/main.pd 
[r gaia.temp]
|
[clip -10 45]        ← protege contra valores absurdos
|
[* 8]
|
[+ 220]              ← 20 °C vira 380 Hz, 30 °C vira 460 Hz
|
[osc~]
|
[*~ 0.05]            ← volume baixo, cuide de quem escuta
|
[dac~]

Três cuidados que valem a peça

  • Sempre limite a entrada com [clip]. Um sensor com defeito pode mandar um número estranho, e você não quer isso virando estouro no alto-falante.
  • Os dados chegam devagar. O clima só muda quando o público move o globo. Para movimento contínuo, use o dado como destino e interpole — com [line], por exemplo.
  • Comece baixo. A peça pode tocar numa exposição, com o volume do sistema alto.

A ficha da obra: patch.json

minha-peca/patch.json 
{
  "$schema": "../../schemas/gaia.patch.schema.json",
  "schemaVersion": 1,
  "id": "minha-peca",
  "label": "Minha Peça",
  "description": "Uma frase sobre a obra.",
  "author": { "name": "Seu Nome" },
  "license": "CC-BY-4.0",
  "build": { "initialMemory": 64 },
  "activation": {
    "moments": ["player"],
    "compositions": ["lightningBolts"]
  }
}
  • id igual ao nome da pasta — minúsculas e hífen.
  • moments: "player" se toca junto com uma animação, "map" se é a paisagem sonora do globo.
  • compositions: com qual animação ela toca. Remova a linha se for som do globo.
  • initialMemory: 64 MB serve para quase tudo. Suba para 128 ou 256 com muitas vozes ou samples grandes.
Caminho B · imagem

Uma animação p5.js

Uma animação declara quais dados usa, e o site os entrega prontos. Você não busca nada, não chama nenhuma API, não trata erro de rede: os números chegam como propriedades do seu sketch.

Dois arquivos

compositions/minha-animacao/ 
compositions/minha-animacao/
├── composition.json     a ficha da obra
└── sketch.tsx           o seu p5

A pasta usa minúsculas e hífen. Se a obra tiver som próprio, os .mp3 vão em public/audios/.

Os onze dados que você pode pedir

Peça só o que a obra realmente lê — pedir dado que não se usa faz o site buscar informação à toa.

Cada dado tem um nome só. Não existe apelido nem grafia alternativa: é windSpeed, nunca windspeed. Se você errar, o sistema recusa o envio e sugere a grafia certa — em vez de aceitar calado e deixar o valor parado em zero, que era o que acontecia antes.

Monte a sua ficha

Marque o que a obra usa e copie o resultado. É o arquivo composition.json, pronto.

A pasta se chama chuva-de-verao — com hífen — e o id vai em camelCase. Parece pegadinha, mas a pasta é um nome de arquivo e o id vira um identificador dentro do código.

Se você escolheu regras, os limiares saem em branco de propósito: quanto é “muita chuva” depende da sua obra, e um número chutado daria um manifesto que valida e decide errado. Troque os zeros e os nomes AJUSTE-… pelos seus.

O sketch

O contrato é curto: exporte um componente por padrão, e ele recebe os dados que você declarou — cada um com o nome exato do attributes — mais um play.

compositions/exemplo-clima/sketch.tsx · é o da abertura 
"use client";
import type { P5CanvasInstance, SketchProps } from "@p5-wrapper/react";
import { NextReactP5Wrapper } from "@p5-wrapper/next";

export type ChuvaDeVeraoProps = {
  play: boolean;
  temperature: number;
  rain: number;
};

function sketch(p5: P5CanvasInstance<SketchProps & ChuvaDeVeraoProps>) {
  let temperature = 0;
  let rain = 0;
  let play = false;

  p5.setup = () => {
    p5.createCanvas(p5.windowWidth, p5.windowHeight);
    p5.colorMode(p5.HSB, 255);
    p5.noStroke();
    if (!play) p5.noLoop();
  };

  // Chamado sempre que um dado muda — é por aqui que o clima entra.
  p5.updateWithProps = (props: ChuvaDeVeraoProps) => {
    if (!Number.isNaN(props.temperature)) temperature = props.temperature;
    if (!Number.isNaN(props.rain)) rain = props.rain;
    play = props.play;
    if (play) p5.loop();
    else p5.noLoop();
  };

  p5.draw = () => {
    const matiz = p5.map(temperature, -10, 45, 160, 0, true);
    p5.background(matiz, 180, 90);
    p5.fill(matiz, 60, 255);
    for (let i = 0; i < rain * 4; i++) {
      p5.circle(p5.random(p5.width), p5.random(p5.height), 3);
    }
  };
}

export default function ChuvaDeVeraoSketch(props: ChuvaDeVeraoProps) {
  return <NextReactP5Wrapper sketch={sketch} {...props} />;
}

Três coisas que salvam tempo

  • Respeite o play. Quando é falso a obra está fora de cena: chame p5.noLoop(). Uma animação rodando escondida come bateria de quem só está olhando o mapa.
  • Nunca confie no valor bruto. Use p5.map(..., true) com o quarto argumento, ou p5.constrain. Um dia de tempestade manda número muito maior do que você testou.
  • Zero é um valor legítimo. Sem chuva, rain vale 0 — e a obra precisa continuar bonita assim, porque é o estado mais comum.

Vindo do OpenProcessing?

O código de lá quase sempre funciona com três ajustes: envolva tudo na função sketch(p5) e ponha p5. na frente das chamadas (background(0) vira p5.background(0)); function setup() vira p5.setup = () => {}, o mesmo para draw; e onde havia um slider para experimentar, entra o dado do clima.

De onde vem o som da animação

Se a obra não usa Pd, você fornece os arquivos e diz quando cada um toca. Vale a primeira regra que couber, de cima para baixo — arraste e veja:

Simulador de regras · a primeira que couber vence —

A última regra não tem condição: ela cobre todo o resto. Sem ela existe um estado do clima em que a obra fica muda, e o sistema avisa.

Os quatro operadores

OperadorSignifica
minmaior ou igual a

Uma regra pode olhar dois dados ao mesmo tempo, e aí os dois precisam bater:

duas condições numa regra 
{ "when": { "fireCount": { "min": 4 }, "closeFires": { "min": 2 } },
  "file": "fogo-intenso.mp3" }

A ordem importa mais do que parece. Duas animações do projeto tinham a mesma condição escrita duas vezes; a segunda nunca era alcançada, e um arquivo de áudio jamais tocou. O verificador agora reclama quando uma regra torna outra inalcançável.

Todo dado que aparece num when precisa estar em attributes — senão ele nunca seria buscado, valeria zero, e a regra decidiria sempre errado. O sistema recusa o envio nesse caso.

Som + imagem

Os dois juntos

Se você tem a animação e o patch que a sonoriza, mande os dois no mesmo pull request. A ligação é declarada de um lado só, no patch.json:

patch.json · a ligação 
"activation": {
  "moments": ["player"],
  "compositions": ["chuvaDeVerao"]
}

Use ali o id da animação — o camelCase, não o nome da pasta. E no composition.json dela, diga que o som vem de fora: "audio": { "kind": "patch" }.

Pronto. O robô entende que os dois são uma obra só e manda um link, que abre a animação já com o patch tocando.

Do envio ao ar

A jornada

O caminho é o mesmo para patch, para animação, ou para os dois.

  1. Abra a pasta certa

    …/tree/main/patches para patches. …/tree/main/compositions para animações.

  2. “Add file” → “Upload files”

    No canto superior direito da lista de arquivos. Se o botão não aparece, o convite ainda não foi aceito.

  3. Arraste a pasta inteira

    O GitHub preserva a estrutura, então Libs/ continua no lugar certo. Não descompacte nem reorganize antes. Arquivos de áudio da animação vão em public/audios/.

  4. Crie uma branch e abra o pull request

    No fim da página, escolha “Create a new branch for this commit and start a pull request”. Dê um nome à branch e confirme.

    Traduzindo o jargão. Uma branch é uma cópia paralela onde a sua obra vive até ser aprovada. Um pull request é o pedido para incorporá-la. Nada disso afeta o site no ar até alguém aprovar.

  5. Espere alguns minutos

    O robô assume daqui:

    Ele fazVocê vê
    Confere a ficha da obra✓ ou um erro explicado em português
    Compila o patch, se houverUm comentário com tamanho e memória
    Registra a animação, se houverUm commit do robô na sua branch
    Espera a Vercel publicar—
    Escreve o linkO botão para ver e ouvir

    O commit do robô na sua branch é esperado: são arquivos que o site precisa e que ninguém escreve à mão.

  6. Veja e ouça

    São dois cliques até o som: primeiro Iniciar, depois o botão com o nome da obra. Não é burocracia — o navegador só libera áudio depois de um gesto seu, e um link que já caísse dentro da animação mostraria a imagem e ficaria mudo.

    Se a obra tem som de arquivo, procure ainda o Unmute no canto: o som começa desligado.

  7. Ajuste quantas vezes quiser

    Suba o arquivo corrigido na mesma branch e o robô refaz tudo sozinho. Não abra um pull request novo.

  8. Avise que está pronto

    Um comentário no pull request dizendo que a obra está do jeito que você quer. Alguém da equipe revisa e publica.

    Um último passo é da equipe. Ver a obra pelo link funciona assim que o robô termina. Mas para ela entrar no rodízio automático — aquele em que o site escolhe sozinho o que mostrar conforme o clima — alguém precisa incluí-la na lista de obras ativas. É decisão curatorial, não técnica: peça no pull request.

Quando dá errado

Diz que está tocando e não sai som

Quatro causas, em ordem de frequência:

  1. O som começa desligado

    Procure o Unmute no canto superior esquerdo. Enquanto ele disser “Unmute”, está mudo.

  2. Faltou o clique

    O navegador só libera áudio depois de um gesto seu. Chegou por um link? Clique em Iniciar e depois no nome da obra.

  3. O navegador bloqueou

    Se ele pedir permissão, aceite.

  4. A obra depende de um dado que agora vale zero

    Um patch de trovão só soa quando cai raio de verdade. Num dia calmo ele fica em silêncio — e está certo.

Como testar quando o dado está zerado

Com a obra tocando, abra o console do navegador — tecla F12, aba Console — e mande o valor você mesmo:

console do navegador 
Pd4Web.sendBang("bolt")
Pd4Web.sendFloat("gaia.temp", 38)
Pd4Web.sendFloat("gaia.rain", 12)

É a maneira mais rápida de separar “está funcionando, só não tem dado” de “está quebrado”.

Para uma animação, o equivalente é abrir o link do preview trocando o lugar: ?lat=-3.1&lng=-60.0 põe o globo em Manaus, onde chove muito mais.

A animação abre em preto

Quase sempre é o play: se o sketch chama p5.noLoop() e nunca volta a chamar p5.loop() quando play fica verdadeiro, ele desenha um quadro e para. Confira o updateWithProps do exemplo.

O robô reclamou de um nome

Ele sugere a grafia certa. Os nomes são exatos, incluindo maiúsculas: windSpeed, lightningCount, closeFires.

Perguntas

As que sempre aparecem

Quero um dado que não está na lista.

Peça no pull request, dizendo qual e para quê. Acrescentar um dado novo é trabalho de programação e leva alguns dias — mas depois fica disponível para todo mundo, para sempre.

Meu patch usa uma biblioteca externa (else, cyclone…).

Pode funcionar, pode não funcionar. O robô avisa se o objeto não existir no compilador. Se for essencial, comente pedindo — dá para incluir, mas isso aumenta o tamanho do site para todo visitante, então é decisão da equipe.

Minha animação usa uma biblioteca de p5 (p5.sound, addons…).

Pergunte antes de contar com ela. O projeto carrega o p5 base; cada adição pesa para todo visitante.

Minha obra não usa dado nenhum. Tem problema?

Nenhum. O sistema avisa que ela não escuta nada, mas é só um aviso. Muitas obras são assim.

Posso ver ou ouvir antes de enviar?

Um patch, sim, no Pd mesmo: os objetos [r gaia.*] simplesmente não recebem nada localmente — ligue um [number] neles para testar valores à mão. Uma animação, no editor do p5 ou no OpenProcessing, trocando os dados do clima por sliders enquanto compõe.

Enviei e não aconteceu nada.

Confira se você criou mesmo o pull request, e não apenas subiu os arquivos. Se criou e o robô não respondeu em quinze minutos, escreva um comentário marcando alguém da equipe.

Posso usar áudio de terceiros?

Só com licença compatível. O formulário de envio pede essa confirmação, e ela é levada a sério: o GaiaSenses é público.
